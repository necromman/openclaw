# 기능 갭 분석 — 오픈소스 IAM 대비 IX-Auth

> 2026-08-08 조사. Keycloak · Authentik · Zitadel · Authelia 를 훑고, **IX-Auth 의 경계 안에서** 필요한 것만 골랐다.

## 먼저 — 비교 대상이 같지 않다

| | Keycloak / Authentik / Zitadel | IX-Auth |
|---|---|---|
| 정체 | **여러 앱에 로그인을 제공하는 IdP** | **앱 하나가 스스로 인증** |
| 배포 | 독립 서버 + 전용 DB (+Redis) | 앱과 같은 배포 단위, 앱 DB 공유 |
| 프로토콜 | OIDC·OAuth2·SAML·LDAP·RADIUS | 자체 JWT (OIDC 관례) |
| 화면 | 로그인·동의·계정 화면 내장 | **없음** (앱이 만든다) |

**그래서 기능 목록을 그대로 옮기면 안 된다.** 저들의 기능 상당수는 "IdP 이기 때문에" 필요한 것이고, IX-Auth 에서는 존재 이유가 없거나 IX-Trust 의 몫이다.

이 문서는 셋으로 나눈다 — **① 채울 것 ② 고칠 것 ③ 넣지 않을 것.**

---

## ① 없는데 있어야 하는 것

우선순위는 "없으면 운영에서 곤란한 순서" 다.

### P1 — 없으면 곤란하다

| 기능 | 왜 필요한가 | 규모 |
|------|------------|------|
| **TOTP 2단계 인증** | 스키마(`mfa_credentials`)만 있고 구현이 없다. 관리자 계정 보호의 기본선이고, 고객사 보안 검토에서 가장 먼저 묻는다 | 중 |
| **백업 코드** | MFA 를 켜면 반드시 따라와야 한다. 휴대폰을 잃으면 관리자도 못 들어가는 상황이 생긴다 | 소 |
| **본인 탈퇴 / 계정 삭제 요청** | 개인정보 처리 요구사항. 지금은 관리자 소프트 삭제뿐이고 본인이 요청할 길이 없다 | 소 |
| **로그인 알림** | 새 기기·새 IP 로그인 시 메일. 계정 탈취를 사용자가 **스스로 알아채는 유일한 수단**이다. 세션 목록은 들여다봐야 보인다 | 소 |
| **동시 세션 제한** | 계정 공유를 막아야 하는 유상 서비스에서 요구된다. 초과 시 가장 오래된 세션을 끊는다 | 소 |

### P2 — 곧 요구받는다

| 기능 | 왜 필요한가 | 규모 |
|------|------------|------|
| **매직 링크 로그인** | 비밀번호 없이 메일 링크로 로그인. 토큰·메일 인프라가 이미 있어 붙이기 쉽고, "비밀번호를 안 만들어도 되는" 서비스 수요가 크다 | 소 |
| **Google 로그인** | MS·카카오·네이버는 있는데 Google 이 없다. provider 추상화가 있어 클래스 하나면 된다 | 소 |
| **비밀번호 재사용 이력** | 지금은 직전 것만 막는다. 공공·금융 요구사항에 "최근 N개 재사용 금지" 가 흔하다 | 소 |
| **유출 비밀번호 차단** | HIBP 등의 목록과 대조. 복잡도 규칙보다 실효가 크다. **다만 외부 API 호출이라 폐쇄망에서는 못 쓴다** — 설정으로 끄고 켠다 | 중 |
| **약관 동의 관리** | 가입 시 필수/선택 동의 항목, 버전 관리, 재동의 요구. 대외 서비스에 사실상 필수 | 중 |
| **CAPTCHA** | 가입·로그인 봇 방지. 속도 제한만으로는 분산 시도를 못 막는다. 외부 서비스 연동이라 설정으로 | 중 |
| **사용자 속성 스키마** | `attributes` JSONB 는 있는데 정의·검증이 없다. 부서·사번 같은 것을 넣을 때 앱마다 제각각이 된다 | 중 |
| **사용자 일괄 등록** | 초기 도입 시 수백 명을 손으로 넣을 수 없다. CSV 업로드 → 초대 메일 일괄 발송 | 소 |

### P3 — 있으면 좋다

| 기능 | 비고 |
|------|------|
| **감사 로그 내보내기** | CSV. 보안 감사 때 요구된다 |
| **본인 로그인 이력 화면** | 세션 목록과 별개로 "언제 어디서 로그인했나" |
| **메일 템플릿 편집** | 지금은 웹훅으로 앱이 대신 만드는 방법뿐. 관리 화면에서 제목·본문을 바꾸게 |
| **다국어** | 메일 본문이 한국어 고정. 해외 고객사가 생기면 필요 |
| **step-up 인증** | 민감 작업 시 재인증. 비밀번호 변경은 이미 현재 비밀번호를 요구하므로 부분 대응됨 |
| **서명 키 자동 회전** | `key-rotation-days` 설정만 있고 스케줄러가 없다 |

## ② 있는데 고칠 것

| 대상 | 지금 | 문제 | 개선 |
|------|------|------|------|
| **세션 목록** | UA 문자열 그대로 표시 | 사용자가 자기 기기를 알아볼 수 없다 (`Mozilla/5.0 (Windows NT…`) | "Chrome · Windows" 로 파싱 |
| **속도 제한** | 인스턴스 메모리 | 2대면 실질 한도가 2배. 문서에 적어 두었지만 근본 해결은 아니다 | DB 기반 카운터 또는 앞단 위임 안내 강화 |
| **메일 발송** | 실패를 삼킨다 | 운영자가 "안 갔다" 는 것을 로그로만 안다. 재시도도 없다 | 발송 이력 표 + 실패 재시도 + 화면 노출 |
| **관리 화면** | 사용자 목록만 | 상세 화면이 없어 한 사람의 역할·세션·연결계정·이력을 한눈에 못 본다 | 사용자 상세 화면 |
| **감사 로그** | 이벤트·사용자 필터 | 기간 검색이 약하고 내보내기가 없다 | 필터 보강 + CSV |
| **소셜 연결** | API 만 있음 | 사용자가 자기 연결을 보고 끊을 화면이 앱에만 있다 (데모에도 없음) | 데모에 참조 구현 추가 |
| **키 회전** | 설정만 존재 | 90일이 지나도 아무 일도 없다 | 스케줄러 + 이전 키 유예 |
| **설정 변경 이력** | 감사 로그에만 | 설정 화면에서 "이 값을 누가 언제 바꿨나" 를 못 본다 | 항목별 이력 표시 |

## ③ 넣지 않을 것 — 경계

Keycloak 등에는 있지만 **IX-Auth 에 넣으면 제품이 무너진다.** 요청이 오면 IX-Trust 승격을 제안한다.

| 기능 | 왜 안 되는가 |
|------|-------------|
| **OIDC/OAuth2 Authorization Server** | "다른 앱에 로그인을 제공" 하는 순간 IX-Auth 가 아니라 IdP 다. 그게 IX-Trust 다 |
| **SAML IdP** | 위와 같다. 게다가 SAML 은 구현·운영 비용이 크다 |
| **LDAP / RADIUS / Kerberos** | 프로토콜 서버를 띄우면 외부 노출이 필요해지고 불변식 4 가 깨진다 |
| **SCIM 프로비저닝** | 여러 시스템 간 사용자 동기화 = 멀티앱 전제 |
| **멀티테넌시 · 조직/부서 트리** | 앱 하나를 위한 제품이다. 조직 모델을 넣으면 그룹만으로 되던 것이 복잡해진다 |
| **인증 플로우 빌더** (Authentik 의 flow) | 화면을 IX-Auth 가 그리지 않으므로(불변식 1) 성립하지 않는다 |
| **포워드 프록시 인증** | 앱 앞단에 서는 순간 외부 노출과 가용성 결합이 생긴다 |
| **토큰 교환 / 위임** | 멀티앱·서비스 간 위임 시나리오 |
| **관리 워크플로 자동화** | Keycloak 26.6 의 신기능이지만, 사용자 수백 명 규모에서는 과하다 |

### 재검토가 필요한 하나 — WebAuthn / Passkey

경계 문서의 제외 목록에 있지만, **2026년 현재 상황이 달라졌다.** 브라우저·OS 지원이 보편화됐고 "비밀번호 없는 로그인" 요구가 실제로 들어온다.

다만 **검증은 앱이 아니라 IX-Auth 가 해야 하고**(챌린지 상태를 서버가 들고 있어야 한다), 등록·인증 화면은 앱이 만들어야 한다. 불변식과 충돌하지는 않는다.

→ **결정 대기 항목으로 올린다.** 넣는다면 P2, 규모는 중이다.

---

## 권장 순서

```
1) TOTP + 백업 코드          ← 보안 검토에서 가장 먼저 묻는다
2) 로그인 알림 · 동시 세션 제한 · 본인 탈퇴   ← 작고 효과가 크다
3) 세션 목록 기기 표시 · 메일 발송 이력       ← 있는 것의 완성도
4) 매직 링크 · Google 로그인                 ← 인프라가 이미 있다
5) 약관 동의 · 사용자 속성 스키마            ← 대외 서비스 요구
```

**P3 실적용 전에 이 목록을 다 채우지 않는다.** 첫 적용에서 무엇이 정말 필요한지가 드러나고, 그때 우선순위가 바뀔 가능성이 높다.

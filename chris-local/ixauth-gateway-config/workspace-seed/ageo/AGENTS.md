# AGENTS.md - AGEO 에이전트의 작업 절차

이 파일은 일하는 순서와 보고 형식을 정한다. 정체성은 `IDENTITY.md`, 태도는 `SOUL.md` 에 있다.

## 1. 스킬을 먼저 연다

작업 폴더의 `skills/` 에 네 개가 있다. 해당하는 작업이면 스킬 문서를 열어 그 절차를 따른다. 기억으로 대신하지 않는다.

| 스킬 | 언제 쓰나 |
| --- | --- |
| `aeo-page-audit` | 페이지 한 개의 AEO/GEO 상태를 점검하고 점수를 낼 때 |
| `aeo-crawler-access` | robots.txt 로 AI 크롤러가 막혀 있는지 볼 때 |
| `aeo-schema-jsonld` | 구조화 데이터(JSON-LD)를 검증하거나 새로 만들 때 |
| `aeo-health-claims-guard` | 건강기능식품 문안을 만들거나 검사할 때 (문안 생성 시 항상) |

## 2. 감사 요청을 받았을 때의 순서

"이 상세페이지 봐 줘", "우리 페이지가 AI 검색에 안 나온다" 같은 요청은 아래 순서로 처리한다. 앞 단계를 건너뛰지 않는다. 앞 단계의 실패가 뒤 단계의 원인인 경우가 많기 때문이다.

1. **수집.** `web_fetch` 로 대상 URL 의 HTML 을 받는다. 본문 텍스트가 거의 없으면 `browser` 로 다시 연다. 받아 온 것과 화면에 보이는 것이 다르면 그 차이 자체가 발견 사항이다.
2. **크롤러 접근 진단.** `aeo-crawler-access` 절차대로 `robots.txt` 를 받아 판정표를 만든다. 응답 크롤러가 막혀 있으면 나머지 개선은 전부 무의미하므로 여기서 결론을 먼저 알린다.
3. **구조 감사.** `aeo-page-audit` 체크리스트로 직답 블록·헤딩·표·FAQ·텍스트 비율·alt·최신성·엔티티 일관성을 센다. 숫자를 실제로 센다.
4. **스키마 검증.** `aeo-schema-jsonld` 로 기존 JSON-LD 를 뽑아 필수 속성을 대조하고, 없으면 템플릿을 채워 제안한다.
5. **규제 검사.** `aeo-health-claims-guard` 로 페이지의 기존 문구와 내가 새로 쓴 문구를 모두 검사한다. 위반은 개선안보다 위에 둔다.
6. **점수와 개선안 보고서.** 아래 형식으로 낸다.

## 3. 보고서 형식

````markdown
# AEO/GEO 감사 - <페이지 이름>

- 대상 URL: <URL>
- 점검 일시: <YYYY-MM-DD HH:MM KST>
- 수집 방법: web_fetch / browser (렌더링 필요 여부)
- 총점: <0~100> 점

## 결론 3줄
1. <가장 중요한 발견>
2. <두 번째>
3. <세 번째>

## 규제 경고
| 위치 | 문구 | 유형 | 대체안 |
| --- | --- | --- | --- |
(없으면 "발견된 금칙 표현 없음" 한 줄)

## 항목별 판정
| 항목 | 현재 | 판정 | 우선순위 | 근거 |
| --- | --- | --- | --- | --- |

## 먼저 할 것
1. <작업> - 예상 효과, 담당
2. ...
3. ...

## 붙임: 제안 코드/문안
(JSON-LD, HTML 표, FAQ 문안)

## 출처
- <실제로 연 URL 목록>
````

## 4. 규칙

- **센 것만 적는다.** 점수는 `aeo-page-audit` 의 산식으로 계산하고 계산 과정을 남긴다. 감으로 점수를 주지 않는다.
- **못 본 것은 못 봤다고 적는다.** 로그인이 필요한 페이지, 차단된 요청, 응답하지 않은 도구는 보고서에 그대로 쓴다.
- **긴 산출물은 파일로 남긴다.** 보고서가 길면 작업 폴더에 `.md` 로 저장하고 대화에는 결론과 표만 낸다.
- **한 번에 한 페이지.** 여러 URL 을 받으면 페이지마다 따로 감사하고 마지막에 비교표를 붙인다.
- **재감사 요청이면 이전 보고서를 먼저 찾는다.** 작업 폴더에 있으면 무엇이 고쳐졌는지 대조해서 낸다.

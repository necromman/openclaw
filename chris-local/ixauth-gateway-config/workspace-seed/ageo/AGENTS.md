# AGENTS.md - AGEO 에이전트의 작업 절차

이 파일은 일하는 순서와 보고 형식을 정한다. 정체성은 `IDENTITY.md`, 태도는 `SOUL.md`, 회사와 쇼핑몰 사실은 `COMPANY.md` 에 있다.

## 0. 세션을 시작할 때

1. **`COMPANY.md` 를 먼저 읽는다.** 회사·상품·도메인·플랫폼 제약·이미 확인된 문제와 "확인 못 한 것" 목록이 거기 있다. 기억으로 대신하지 않는다.
2. 사용자가 **URL 없이** "우리 상세페이지", "우리 제품" 이라고 하면 기본 대상은 **라포르몰 상품 상세**다. 특정 상품을 말하지 않으면 대표 상품인 "라포르 프리미엄 숙면베개 바로베개"(`https://www.cstpillow.com/goods/goods_view.php?goodsNo=7`)로 가정하고, 가정한 사실을 한 줄로 밝힌 뒤 진행한다.
3. 메디월드몰(`www.mediworldmall.com`)은 로그인 벽 뒤라 인용 대상이 되지 않는다. 요청이 그쪽이면 그 사실을 먼저 알리고, 메디월드몰 문안을 라포르몰로 옮기는 일은 하지 않는다.
4. `COMPANY.md` 의 실측치는 2026-09-14 기준이다. 그 값을 근거로 쓸 때는 조사일을 함께 적고, 중요한 판단이면 해당 페이지를 다시 받아 본다.

## 1. 스킬을 먼저 연다

작업 폴더의 `skills/` 에 네 개가 있다. 해당하는 작업이면 스킬 문서를 열어 그 절차를 따른다. 기억으로 대신하지 않는다.

| 스킬 | 언제 쓰나 |
| --- | --- |
| `ageo-claims-guard` | 문안을 만들거나 검사할 때 (문안 생성 시 항상). 의료기기 오인 광고·과장·후기·필수 표기 |
| `aeo-crawler-access` | robots.txt 로 AI 크롤러가 막혀 있는지 볼 때 |
| `aeo-page-audit` | 페이지 한 개의 AEO/GEO 상태를 점검하고 점수를 낼 때 |
| `aeo-schema-jsonld` | 구조화 데이터(JSON-LD)를 검증하거나 새로 만들 때 |

## 2. 감사 요청을 받았을 때의 순서

"이 상세페이지 봐 줘", "우리 페이지가 AI 검색에 안 나온다" 같은 요청은 아래 순서로 처리한다. 앞 단계를 건너뛰지 않는다. 앞 단계의 실패가 뒤 단계의 원인인 경우가 많다.

1. **수집.** `web_fetch` 로 대상 URL 의 HTML 을 받는다. 본문 텍스트가 거의 없으면 `browser` 로 다시 연다. 받아 온 것과 화면에 보이는 것이 다르면 그 차이 자체가 발견 사항이다. 라포르몰 상세는 통이미지라 HTML 텍스트가 1,262자 수준인 것이 정상 상태다.
2. **규제 감사.** `ageo-claims-guard` 로 페이지의 기존 문구를 전수 검사한다. 이미지 속 글자까지 옮겨서 본다. 의료기기 오인 광고는 시정 명령과 접속 차단이 따라오므로 다른 어떤 개선보다 먼저 보고한다.
3. **크롤러 접근 진단.** `aeo-crawler-access` 절차대로 `robots.txt` 를 받아 판정표를 만든다. 응답 크롤러가 막혀 있으면 나머지 개선이 무의미하므로 여기서 결론을 먼저 알린다.
4. **구조 감사.** `aeo-page-audit` 체크리스트로 직답 블록·헤딩·표·FAQ·텍스트 비율·alt·최신성·엔티티 일관성을 센다. 숫자를 실제로 센다.
5. **스키마 검증.** `aeo-schema-jsonld` 로 기존 JSON-LD 를 뽑아 필수 속성을 대조하고, 없으면 템플릿을 채워 제안한다. 라포르몰은 현재 0건이므로 대개 생성 작업이 된다.
6. **내가 새로 쓴 문안 재검사.** 2단계 사전을 새 문안에도 돌린다. 대체안이 또 다른 위반인 사고가 흔하다.
7. **점수와 개선안 보고서.** 3절 형식으로 낸다.

## 3. 라포르몰 우선 작업 10개

개별 요청이 없을 때 제안하는 기본 순서다. 근거는 2026-09-14 조사다. 작업을 고를 때 이 순서를 기준으로 삼고, 순서를 바꾸면 이유를 적는다.

| 순위 | 작업 | 요지 |

## 5. 규칙

- **규제가 점수보다 위다.** 위반이 하나라도 있으면 보고서 맨 위에 둔다. 점수를 깎지는 않는다. 두 문제는 성질이 다르다.
- **센 것만 적는다.** 점수는 `aeo-page-audit` 의 산식으로 계산하고 계산 과정을 남긴다. 감으로 점수를 주지 않는다.
- **못 본 것은 못 봤다고 적는다.** 로그인이 필요한 페이지, 차단된 요청, 응답하지 않은 도구는 보고서에 그대로 쓴다.
- **`COMPANY.md` 6절 항목을 사실처럼 말하지 않는다.** 확인 못 한 것은 담당자 확인 요청으로 낸다.
- **긴 산출물은 파일로 남긴다.** 보고서가 길면 작업 폴더에 `.md` 로 저장하고 대화에는 결론과 표만 낸다.
- **한 번에 한 페이지.** 여러 URL 을 받으면 페이지마다 따로 감사하고 마지막에 비교표를 붙인다.
- **재감사 요청이면 이전 보고서를 먼저 찾는다.** 작업 폴더에 있으면 무엇이 고쳐졌는지 대조해서 낸다.
- **고도몰5 제약 안에서 제안한다.** 되는 것과 안 되는 것은 `COMPANY.md` 4절에 있다. 안 되는 일을 시키지 않는다.

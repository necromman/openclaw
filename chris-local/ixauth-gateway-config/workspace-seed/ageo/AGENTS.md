# AGENTS.md - AGEO 에이전트의 작업 절차

이 파일은 일하는 순서와 보고 형식을 정한다. 정체성은 `IDENTITY.md`, 태도와 기준 답변 형식은 `SOUL.md`, 회사와 쇼핑몰 사실은 `COMPANY.md`, 완성된 감사 예시는 `PLAYBOOK.md` 에 있다.

## 0. 세션을 시작할 때

1. **`COMPANY.md` 와 `PLAYBOOK.md` 를 먼저 읽는다.** 회사·상품·도메인·플랫폼 제약·이미 확인된 문제와 "확인 못 한 것" 목록이 거기 있다. 기억으로 대신하지 않는다.
2. 사용자가 **URL 없이** "우리 상세페이지", "우리 제품" 이라고 하면 기본 대상은 **라포르몰 상품 상세**다. 특정 상품을 말하지 않으면 대표 상품인 "라포르 프리미엄 숙면베개 바로베개"(`https://www.cstpillow.com/goods/goods_view.php?goodsNo=7`)로 가정하고, 가정한 사실을 한 줄로 밝힌 뒤 진행한다.
3. 메디월드몰(`www.mediworldmall.com`)은 로그인 벽 뒤라 인용 대상이 되지 않는다. 요청이 그쪽이면 그 사실을 먼저 알리고, 메디월드몰 문안을 라포르몰로 옮기는 일은 하지 않는다.
4. `COMPANY.md` 의 실측치는 2026-09-14 기준이다. 그 값을 근거로 쓸 때는 조사일을 함께 적고, 중요한 판단이면 해당 페이지를 다시 받아 본다.

## 2. 전략: GEO 는 후순위, AEO 가 본체

**GEO(생성엔진 최적화)는 처방 목록에서 뺀다.** GEO 는 모델이 이미 학습한 내용으로 답할 때 우리 브랜드가 나오게 만드는 일이다. 그런데 어떤 문서가 학습 데이터에 들어가는지는 모델의 학습 컷오프가 정하고, 컷오프도 학습 여부도 우리가 통제할 수 없다. 오늘 페이지를 고쳐도 다음 학습에 들어갔는지 확인할 방법이 없고, 들어갔다 해도 몇 달 뒤에 반영된다. 그래서 GEO 를 과제로 팔지 않고 성과 지표로도 쓰지 않는다.

**AEO(답변엔진 최적화)가 본체다.** AEO 는 모델이 답하는 그 순간 검색·크롤링으로 페이지를 가져와 인용하는 경로다. 페이지를 고치면 다음 크롤에 바로 반영되고, 인용됐는지 검색 화면에서 눈으로 확인할 수 있다. 우리가 손댈 수 있는 곳이 여기뿐이다.

그래서 처방은 언제나 AEO 순서로 낸다.

1. 이미지 속 글자를 HTML 텍스트로 복제
2. 페이지별 title·description 분리
3. Product 스키마(JSON-LD) 삽입
4. 질문형 페이지 신설
5. 위생(sitemap 재생성·html lang·img alt·오타)

**GEO 는 한 줄로만 다룬다.** AEO 가 갖춰져 텍스트가 웹에 남으면 그것이 다음 학습 자료가 되어 GEO 는 따라온다. 먼저 노리는 목표가 아니라 결과다. 사용자가 GEO 를 물으면 이 한 줄로 답하고 AEO 처방으로 돌아온다.

### 2-1. 질문형 페이지 규칙 (4순위 처방의 정본)

질문형 페이지가 AEO 의 본체다. 상품 페이지가 아니라 질문 페이지로 인용을 받는다. 페이지마다 아래 네 줄을 지킨다.

1. **제목은 질문 그대로 쓴다.** "베개 높이 가이드" 가 아니라 "경추베개는 높이를 몇 cm로 해야 하나". 사용자가 실제로 치는 문장을 그대로 `h1` 과 `title` 에 둔다.
2. **첫 두 문장에 결론을 완결된 문장으로 박는다.** 모델은 첫 문단을 통째로 떠간다. 인용의 44.2%가 도입부에서 추출된다. "사람마다 다릅니다" 로 시작하면 인용할 것이 없다.
3. **그다음에 근거를 쓴다.** 수치·구간표·출처. 수면 자세별 cm 구간, 소재별 밀도, 시험기관과 시험 항목과 일자.
4. **끝에 자사 제품을 한 줄 연결한다.** 한 줄이다. 본문을 홍보로 채우면 네이버 콘텐츠 5원칙의 "과도한 홍보" 에 걸려 인용에서 빠진다.

문안은 언제나 `ageo-claims-guard` 를 통과한 뒤에 낸다. 질문 자체에 질환명이 들어가는 주제(예: 사용을 피해야 하는 경우)는 답을 물리 사양과 사용 안내로만 쓰고, 질환·증상 판단은 담당자와 전문가에게 넘긴다. 라포르몰 질문형 페이지 후보 4개는 `COMPANY.md` 2-3 절에 있다.

## 3. 감사 요청을 받았을 때의 순서

"이 상세페이지 봐 줘", "우리 페이지가 AI 검색에 안 나온다" 같은 요청은 아래 순서로 처리한다. 앞 단계를 건너뛰지 않는다. 앞 단계의 실패가 뒤 단계의 원인인 경우가 많다.

1. **수집.** `web_fetch` 로 대상 URL 의 HTML 을 받는다. 본문 텍스트가 거의 없으면 `browser` 로 다시 연다. 받아 온 것과 화면에 보이는 것이 다르면 그 차이 자체가 발견 사항이다. 라포르몰 상세는 통이미지라 HTML 텍스트가 상세 영역 기준 1,262자, 페이지 전체 기준 1,877자(대부분 배송·교환환불 안내) 수준인 것이 현재 상태다. 어느 범위로 셌는지 함께 적는다.
2. **규제 감사.** `ageo-claims-guard` 로 페이지의 기존 문구를 전수 검사한다. 이미지 속 글자까지 옮겨서 본다. 의료기기 오인 광고는 시정 명령과 접속 차단이 따라오므로 다른 어떤 개선보다 먼저 보고한다.
3. **크롤러 접근 진단.** `aeo-crawler-access` 절차대로 `robots.txt` 를 받아 판정표를 만든다. 응답 크롤러가 막혀 있으면 나머지 개선이 무의미하므로 여기서 결론을 먼저 알린다.
4. **구조 감사.** `aeo-page-audit` 체크리스트로 직답 블록·헤딩·표·FAQ·텍스트 비율·alt·최신성·엔티티 일관성을 센다. 숫자를 실제로 센다.
5. **스키마 검증.** `aeo-schema-jsonld` 로 기존 JSON-LD 를 뽑아 필수 속성을 대조하고, 없으면 템플릿을 채워 제안한다. 라포르몰은 현재 0건이므로 대개 생성 작업이 된다.
6. **내가 새로 쓴 문안 재검사.** 2단계 사전을 새 문안에도 돌린다. 대체안이 또 다른 위반인 사고가 흔하다.
7. **보고.** `SOUL.md` 의 기준 답변 형식(측정한 것 -> 왜 치명적인가 -> 우선순위별 처방 -> 한 가지 더)으로 낸다. 형식과 깊이의 기준은 `PLAYBOOK.md` 의 라포르몰 감사 예시이고, 채우는 칸은 5절에 있다. 처방이 없으면 그 답은 미완이다.

## 6. 규칙

- **규제가 점수보다 위다.** 위반이 하나라도 있으면 보고서 맨 위에 둔다. 점수를 깎지는 않는다. 두 문제는 성질이 다르다.
- **센 것만 적는다.** 숫자는 실제로 센 것만 쓰고 세지 못했으면 "측정 못 함" 이라고 적는다. 점수가 필요하면 `aeo-page-audit` 부록의 산식으로 계산하고 계산 과정을 남긴다. 점수는 기본 산출물이 아니다. 기본 산출물은 기준 답변 형식이고, 점수는 요청받거나 재감사 대조가 필요할 때만 붙인다.
- **못 본 것은 못 봤다고 적는다.** 로그인이 필요한 페이지, 차단된 요청, 응답하지 않은 도구는 보고서에 그대로 쓴다.
- **`COMPANY.md` 6절 항목을 사실처럼 말하지 않는다.** 확인 못 한 것은 담당자 확인 요청으로 낸다.
- **긴 산출물은 파일로 남긴다.** 보고서가 길면 작업 폴더에 `.md` 로 저장하고 대화에는 결론과 표만 낸다.
- **한 번에 한 페이지.** 여러 URL 을 받으면 페이지마다 따로 감사하고 마지막에 비교표를 붙인다.

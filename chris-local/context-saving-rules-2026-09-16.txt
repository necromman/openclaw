서브에이전트 컨텍스트 절감 규칙 (2026-09-16)
근거: 세션 $639 중 Opus 캐시 읽기가 약 $400(63%). 사용량의 88%가 150k 컨텍스트 초과, 41%가 idd-worker.
원인은 모델·effort 가 아니라 서브에이전트가 큰 컨텍스트를 매 턴 통째로 다시 읽는 것.

====================================================================
1. 작업 중인 세션에 붙여넣을 통보문 (그대로 복사)
====================================================================

[운영 지시: 컨텍스트 절감 규칙, 지금부터 적용]
사용량 분석 결과 비용의 63%가 서브에이전트 캐시 읽기이고, 88%가 150k 컨텍스트 초과 구간에서 발생했다.
지금부터 아래 규칙을 모든 서브에이전트 스폰과 본인 작업에 적용한다.

1. 서브에이전트 하나가 다루는 작업은 컨텍스트 150k 이내에서 끝나는 크기로 쪼갠다.
   한 에이전트가 오래 살며 컨텍스트를 키우는 것보다 작은 에이전트를 여러 번 띄우는 쪽이 싸다.
2. 탐색과 구현을 한 에이전트에 같이 시키지 않는다.
   먼저 Explore 로 파일 위치와 심볼을 찾고, 구현자는 그 목록의 파일만 연다.
3. 빌드·테스트·lint 출력은 파일로 리다이렉트하고 실패 줄만 grep 해서 읽는다.
   예: pnpm test > /tmp/test.log 2>&1; grep -nE "FAIL|Error|✗" /tmp/test.log | head -40
4. 파일은 필요한 범위만 읽는다. 큰 파일은 offset/limit 또는 sed -n 으로 구간만 읽고, 전체 읽기는 700줄 이하일 때만 한다.
5. 같은 파일을 두 번 읽지 않는다. 수정 후 확인용 재읽기는 하지 않는다(Edit 가 실패하면 에러가 난다).
6. 서브에이전트 최종 보고는 200줄 이내로 요약한다. 변경 파일 목록, 결정 사항, 남은 것만 적고 코드 본문은 넣지 않는다.
7. 서브에이전트 프롬프트에 필요한 파일 경로와 스펙만 넣는다. 대화 이력이나 긴 문서 본문을 통째로 복사해 넣지 않는다.
8. 본인 컨텍스트가 150k 를 넘으면 새 작업으로 넘어가기 전에 /compact 를 한다. 작업이 완전히 바뀌면 /clear 한다.
9. 스폰할 서브에이전트에는 아래 2절의 규칙 블록을 프롬프트 끝에 붙인다.

====================================================================
2. 서브에이전트 프롬프트 끝에 붙이는 규칙 블록 (그대로 복사)
====================================================================

[컨텍스트 절감 규칙]
- 이 작업은 컨텍스트 150k 이내에서 끝내야 한다. 범위를 넘을 것 같으면 지금까지 한 것을 보고하고 남은 것을 목록으로 돌려준다.
- 파일은 지정된 것만, 필요한 구간만 읽는다. 큰 파일은 offset/limit 나 sed -n 으로 구간을 읽는다.
- 빌드·테스트·lint 출력은 파일로 보내고 실패 줄만 grep 해서 읽는다. 전체 로그를 컨텍스트에 넣지 않는다.
- 같은 파일을 두 번 읽지 않는다. 수정 확인용 재읽기를 하지 않는다.
- 저장소 전체 검색은 Grep/Glob 으로 하고 결과는 head 로 40줄 이내로 자른다.
- 최종 보고는 200줄 이내. 변경 파일 목록, 결정 사항, 남은 작업만 적고 코드 본문은 넣지 않는다.

====================================================================
3. 감독 세션(메인) 자체 규칙
====================================================================

- 모델 배분은 유지: 감독 Fable medium, 작업자 Opus 기본 effort(high). 실패한 어려운 작업만 Fable 로 재시도.
- 서브에이전트 하나에 "전부 다 해라"를 주지 않는다. 탐색 → 구현 → 검증을 각각 별도 에이전트로 나눈다.
- 서브에이전트 결과를 메인 컨텍스트에 그대로 쌓지 않는다. 요약만 남기고 큰 결과는 파일로 받는다.
- 작업 전환 시 /compact, 완전히 다른 작업이면 /clear.
- /usage 로 "150k 초과 비중"과 "서브에이전트별 비중"을 주기적으로 본다. 150k 초과 비중이 50% 아래로 내려오면 규칙이 먹은 것.

====================================================================
4. 기대 효과
====================================================================

- 캐시 읽기 토큰이 절반 이하로 떨어지면 세션 비용 30~50% 절감.
- 모델·effort 변경보다 효과가 크고 품질 손실이 없다.

용어 설명
컨텍스트: 모델이 한 번의 요청에서 함께 보는 대화·파일·도구 출력의 총량. 150k 는 약 15만 토큰을 뜻한다.
토큰: 모델이 글을 세는 단위. 한국어는 글자 한두 개, 영어는 단어 조각 하나가 토큰 하나에 해당한다.

# 앱 내 사용자 관리 정본

> 관리자가 사람을 추가·수정·삭제하는 화면과 그 뒤의 게이트웨이 표면이다. 계정이 생기는 두 길(초대·자기 가입)은
> [AUTH-SIGNUP.md](AUTH-SIGNUP.md), 로그인·세션은 [AUTH-IXAUTH.md](AUTH-IXAUTH.md), 부서 경계는
> [AUTH-DEPARTMENTS.md](AUTH-DEPARTMENTS.md), 설치는 [DEPLOY.md](DEPLOY.md).
>
> 작성 2026-09-07 (KST). 구현 범위 = F 단계.

---

## 1. 한 문단 요약

관리자는 **설정 > 사용자**(`/settings/users`)에서 목록을 보고, 초대하고, 역할·부서·상태를 바꾸고, 잠금을 풀고, 2단계를 초기화하고, 세션을 끊고, 계정을 지운다. IX-Auth 콘솔로 나가지 않는다. 화면은 게이트웨이의 `/auth/admin/users` 계열만 부르고, 게이트웨이는 그 요청을 **로그인한 관리자 본인의 IX-Auth access token** 으로 중계한다. 즉 IX-Auth 가 권한을 한 번 더 판정하고 원장에 실제 사람이 남는다. 게이트웨이가 추가로 지키는 것은 IX-Auth 가 의견을 갖지 않는 두 가지뿐이다. **누가 누구보다 위인가**(자기 자신·마지막 시스템 관리자·상위 계급 보호)와 **바뀐 권한이 언제 반영되는가**(세션 즉시 종료).

## 2. 화면

경로 `/settings/users`. 설정 사이드바 "연결" 절의 **사용자** 항목과 사이드바 하단 신원 메뉴의 **사용자 관리** 로 들어간다. 두 진입점 모두 `/auth/me` 가 관리 콘솔 링크를 실어 준 세션(= 게이트웨이가 superadmin·admin 으로 판정한 세션)에만 나타난다. 그 밖의 역할이 주소를 직접 쳐서 들어오면 화면은 "관리자만 사용자 관리를 할 수 있습니다" 한 줄을 띄우고, 표면은 어차피 403 이다 (3절).

| 영역      | 내용                                                                                                                              |
| --------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 상단 필터 | 검색(이름·이메일), 상태, 역할, 부서. 필터를 바꾸면 항상 1페이지로 돌아간다                                                        |
| 상단 버튼 | 새로고침, **초대**(패널 토글), **CSV 가져오기**(패널 토글), superadmin 에게만 **고급: IX-Auth 콘솔**                              |
| 목록      | 이름·이메일·역할·부서·상태·마지막 로그인. 25행씩. 이름을 누르면 아래 상세 패널이 열린다                                           |
| 상세 패널 | 표시 이름, 역할 셀렉트, 부서 체크박스, 상태 토글, 행위 버튼(비밀번호 재설정 메일·초대 재발송·잠금 해제·MFA 초기화·세션 종료·삭제) |
| 가입 승인 | 대기 목록과 승인·거절. 설정 > 연결 에 있던 블록을 그대로 옮겼다                                                                   |

역할 표기는 `ui/src/features/ix-auth/ix-auth-role-labels.ts` 한 곳에서 나온다(시스템 관리자·관리자·임원·중재자·직원). 선택지는 초대 화면과 같은 규칙이다. 직원·임원·관리자 3개, superadmin 세션에만 시스템 관리자가 하나 더 붙고, `MODERATOR` 는 **이미 그 역할을 가진 계정을 열었을 때만** 목록에 남는다. 아무도 고르지 않아야 할 항목을 상시로 두면 잘못 고를 길만 생기고, 빼 버리면 패널을 여는 것만으로 강등을 제안하게 된다.

기존 **설정 > 연결** 페이지에서는 초대·가입 승인 블록이 사라지고 계정 블록의 "사용자 관리" 링크만 남는다. 그 링크는 이제 IX-Auth 콘솔이 아니라 이 화면을 가리킨다.

## 3. 게이트웨이 표면

인가는 기존 `/auth/admin/*` 과 완전히 같다. **세션 + superadmin·admin + (변경 메서드면) CSRF**, 레이트리밋 없음, Origin 검사 있음. 판정 코드도 같은 함수(`resolveIxAuthAdminContext`)를 쓴다 - 초대·승인·부서와 사용자 관리가 서로 다른 판정을 갖지 않게 하려는 것이다.

| 메서드 | 경로                                    | 추가 규칙                                                    |
| ------ | --------------------------------------- | ------------------------------------------------------------ |
| GET    | `/auth/admin/users`                     | `query` `status` `role` `department` `page` `size`(최대 100) |
| GET    | `/auth/admin/users/{id}`                | 상세(+세션 수·2단계·주소 확인 여부)                          |
| PATCH  | `/auth/admin/users/{id}`                | 이름·상태. 자기 자신 상태 변경 금지, 이름은 허용             |
| DELETE | `/auth/admin/users/{id}`                | **superadmin 만.** 자기 자신 금지                            |
| PUT    | `/auth/admin/users/{id}/roles`          | 역할 교체. 자기 자신 금지                                    |
| PUT    | `/auth/admin/users/{id}/departments`    | 부서 집합 교체. 자기 자신 금지                               |
| POST   | `/auth/admin/users/{id}/password-reset` | 재설정 **메일** 발송. 링크는 응답에 담기지 않는다 (5절)      |
| POST   | `/auth/admin/users/{id}/invite`         | 초대 재발송. 메일 서버가 없으면 링크를 응답에 담는다         |
| POST   | `/auth/admin/users/{id}/unlock`         | 자동 잠금 해제                                               |
| POST   | `/auth/admin/users/{id}/mfa-reset`      | 2단계 초기화(IX-Auth 가 본인 통지 메일과 감사 로그를 남긴다) |
| DELETE | `/auth/admin/users/{id}/sessions`       | 강제 로그아웃 (4절)                                          |
| POST   | `/auth/admin/users/bulk`                | CSV 가져오기, 상한 500행 (6절)                               |

목록 행은 IX-Auth 가 주는 것에 게이트웨이 판정 두 가지를 얹는다. `gatewayRole`(역할 코드를 `roleMap` 으로 접은 결과)과 `self`(로그인한 관리자 본인인가). 둘 다 브라우저가 다시 계산하면 게이트웨이의 실제 판정과 어긋날 수 있어서 서버가 정한다.

### 3.1 게이트웨이가 추가로 막는 것

IX-Auth 의 `ADMIN` 역할은 `ixauth:*:*` 를 갖는다(V1 마이그레이션). 즉 IX-Auth 만으로는 관리자가 스스로를 시스템 관리자로 올리거나, 마지막 시스템 관리자를 끌어내리거나, 자기 계정을 꺼서 배포 전체를 잠글 수 있다. 그 넷은 게이트웨이 정책이므로 중계 전에 여기서 막는다.

| 규칙                               | 답                     | 이유                                                                                                                 |
| ---------------------------------- | ---------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 자기 자신의 역할·부서·상태·삭제    | 403 `self_forbidden`   | 스스로 강등·비활성하면 되돌릴 사람이 없다. 부서를 스스로 넓히면 타인 세션 열람 경계가 무의미해진다. 이름 변경만 허용 |
| admin 이 SUPERADMIN 부여           | 403                    | 자기보다 높은 계정을 만들어 그것으로 로그인하는 길                                                                   |
| admin 이 superadmin 계정에 행위    | 403                    | 되돌릴 수 있는 사람을 끌어내리게 된다                                                                                |
| 마지막 superadmin 강등·비활성·삭제 | 409 `last_super_admin` | 아무도 관리할 수 없는 배포가 된다                                                                                    |

마지막 시스템 관리자 판정은 IX-Auth 목록 API(`role=SUPERADMIN`, `total`)로 센다. IX-Auth 에는 "마지막 한 명" 개념이 없다. 세는 데 실패하면(신원 서버 불통) **503 으로 거절한다** - 보호를 증명할 수 없는 상태에서 통과시키는 쪽이 더 나쁘다. `superAdminRoles` 에 코드가 여럿 매핑된 배포에서는 코드별 총계 중 **최댓값**을 쓴다. 합계는 한 계정이 두 코드를 함께 가지면 중복으로 세고, 과소 계수는 허용될 변경을 거절할 뿐이라 안전한 방향이다.

## 4. 권한 변경과 즉시 반영

AUTH-IXAUTH 7.3 이 적은 그대로, 역할만 바꾸고 세션을 건드리지 않으면 **최대 15분** 늦게 반영된다. access token 이 그만큼 살아 있기 때문이다. 그래서 역할·부서·비활성·삭제·강제 로그아웃은 전부 같은 정리 절차를 거친다.

1. `DELETE /admin/users/{id}/sessions` - IX-Auth 세션 폐기. 이게 있어야 갱신이 실패한다
2. 게이트웨이 로그인 세션 폐기 - `identity_email` 로 그 사람의 살아 있는 행을 전부 revoke. 브라우저에 이미 있는 쿠키를 죽인다
3. `disconnectClientsForUserProfile(profileId)` - 이미 붙은 WebSocket 종료. D 단계 로그아웃과 같은 배선

응답의 `sessions: {identitySessions, gatewaySessions}` 가 각각 몇 개를 끊었는지 알려 준다.

**알아 둘 것**: 2·3 은 프로필 단위다. 그 사람이 다른 기기에서도 붙어 있었다면 그것도 같이 끊긴다(의도). 그리고 아직 한 번도 로그인하지 않은 계정은 게이트웨이 쪽에 행이 없으므로 `gatewaySessions` 가 0 이다.

## 5. 비밀번호 재설정 링크를 화면에 띄우지 않는 이유

`POST /auth/admin/users/{id}/password-reset` 은 IX-Auth 의 `POST /auth/password/forgot` 으로 중계된다. 즉 **메일을 보낼 뿐이고 링크를 돌려주지 않는다.** 게이트웨이의 mail-hook 은 `kind: "INVITE"` 만 보관하고 `PASSWORD_RESET` 은 버린다(AUTH-SIGNUP 6.1). 재설정 링크는 그 자체가 로그인 자격증명이라, 관리 화면에 떠 있으면 지나가던 사람이 쓸 수 있다.

IX-Auth 의 관리자용 `POST /admin/users/{id}/password-reset` 은 **관리자가 비밀번호를 정해서** 넣는 API 다. 그것을 쓰지 않은 이유는 그 비밀번호를 본인에게 전달하는 경로(메신저·구두)가 대개 가장 약한 고리이기 때문이다.

**메일 서버가 없는 배포**(`mail.transport: WEBHOOK`)에서 관리자가 링크를 손에 넣는 길은 하나다. **초대 재발송** 버튼. IX-Auth 의 `sendInvite` 는 계정 상태를 가리지 않으므로 이미 활성인 계정에도 초대 링크가 나가고, 그 링크를 열면 본인이 새 비밀번호를 정하면서 계정이 다시 `ACTIVE` 가 된다. 화면의 안내문도 그렇게 적혀 있다.

## 6. CSV 가져오기

파일은 브라우저가 읽어 텍스트로 올리고, **게이트웨이가 파싱한다.** 부서가 어느 것이 있는지, 이 관리자가 어떤 역할을 줄 수 있는지는 게이트웨이만 아는 사실이라서다.

```csv
email,name,roles,departments
kim@example.com,김철수,MEMBER,dept-rnd
lee@example.com,이영희,EXECUTIVE,dept-rnd;dept-qa
park@example.com,박민수,ADMIN,
```

| 항목     | 규칙                                                                                     |
| -------- | ---------------------------------------------------------------------------------------- |
| 헤더     | **필수.** 열 이름으로 매핑한다. 위치로 짐작하면 한 칸 밀린 파일을 아무도 눈치채지 못한다 |
| 열 이름  | `email`(필수), `name`/`displayName`, `role`/`roles`, `department`/`departments`          |
| 여러 값  | 역할·부서는 `;` 또는 `\|` 로 나눈다. 쉼표는 CSV 구분자라 따옴표 안에서만 쓸 수 있다      |
| 상한     | 500행. 넘으면 신원 서버를 부르기 전에 400 `too_many_rows`                                |
| 비밀번호 | 만들지 않는다. 전원에게 초대 메일이 나가고 본인이 정한다                                 |
| 실패     | 행 단위. 한 줄이 틀려도 나머지는 들어간다. 결과에 줄 번호와 사유가 나온다                |

**IX-Auth CSV 계약을 그대로 쓰지 않은 근거**: IX-Auth 의 `POST /admin/users/bulk` (text/csv) 는 `email,name,roles` 세 칸뿐이고 부서 열이 없다(`BulkUserImportService.parseCsv`). 부서는 게이트웨이 개념(= `dept-` 접두 그룹 멤버십) 이라 IX-Auth 가 알 수 없다. 그래서 게이트웨이가 파일을 파싱해 부서 열을 떼어 내고, 나머지를 **같은 엔드포인트의 JSON 형태**(`{users:[...], invite:true}`)로 넘긴다. 행마다 독립 트랜잭션이라는 IX-Auth 의 성질은 그대로 얻으면서, 떼어 낸 부서는 응답의 행별 `userId` 로 그룹 멤버십을 붙인다. CSV 로 되직렬화해서 다시 파싱시키는 것은 따옴표 버그를 하나 더 만드는 일일 뿐이다.

역할 열에 이 배포가 모르는 코드가 하나라도 있으면 **파일 전체를 거절한다.** 절반만 넣고 나머지를 보고하면 계급 없는 계정이 생긴다. superadmin 을 요구하는 행이 있는데 호출자가 superadmin 이 아니면 마찬가지로 전체 거절.

## 7. 감사

모든 관리자 행위는 `recordIxAuthAdminAction()` 한 곳을 지난다(`src/gateway/ix-auth-admin-ledger.ts`). 그 함수는 기존 보안 이벤트 콜백(`ix-auth.admin.action`)과 verbose 로그에 더해, **사람 귀속 원장에 `admin_action` 한 줄을 적는다**(H 단계, 정본 [AUTH-AUDIT.md](AUTH-AUDIT.md)). 한 곳으로 모아 둔 덕에 그때 고친 곳은 이 함수 하나였다. 행위 이름은 닫힌 목록이다(`invite`·`user-roles`· `user-departments`·`user-disabled`·`users-imported` 등) - 한 호출부에만 있는 자유 문자열은 나중에 검색할 수 없다.

IX-Auth 자체 원장에는 이미 실제 관리자가 남는다. 중계가 서비스 키가 아니라 그 사람의 토큰을 쓰기 때문이다.

## 8. 한계

| 한계                                                         | 내용                                                                                                                                                                   |
| ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **삭제는 소프트 삭제다**                                     | IX-Auth `DELETE /admin/users/{id}` 는 상태를 `DISABLED` 로 바꾸고 세션을 끊을 뿐 행을 지우지 않는다. 화면 문구도 그렇게 적었다. 완전 삭제 API 는 없다                  |
| **부서 필터는 현재 페이지 안에서만 적용된다**                | IX-Auth 목록 API 에 그룹 필터가 없고 그룹 멤버 조회 API 도 없다. 게이트웨이가 가져온 페이지를 걸러 내고, 응답의 `departmentFilterApplied` 로 화면이 그 사실을 표시한다 |
| **역할은 하나만 고른다**                                     | 표면은 집합 교체(`PUT roles`)이고 여러 개도 받지만, 화면 셀렉트는 하나다. 계급이 둘인 계정은 이 제품에서 의미가 없다                                                   |
| **`ADMIN` 이 IX-Auth 콘솔에서는 여전히 무엇이든 할 수 있다** | 3.1 의 보호는 게이트웨이 표면에만 있다. 콘솔은 IX-Auth 자체 권한 모델로 돈다. 콘솔 링크를 superadmin 에게만 보이게 한 이유이기도 하다                                  |
| **비밀번호 재설정은 메일이 필요하다**                        | 5절. 메일이 없으면 초대 재발송으로 대신한다                                                                                                                            |
| **잠금 해제 버튼은 잠긴 계정에만 눌린다**                    | IX-Auth 의 자동 잠금은 시간이 지나면 스스로 풀린다. 상세 패널이 만료 시각을 보여 준다                                                                                  |
